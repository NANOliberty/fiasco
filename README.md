# 피아스코 온라인

보드게임 RPG [피아스코](https://bullypulpitgames.com/games/fiasco)를 원격으로 함께 플레이하기 위한
상태 공유 보드입니다. 3~5명이 링크 하나로 모여 같은 화면을 보면서, 주사위와 차례와 단계 전환을
앱이 대신 세어 줍니다.

**이야기는 사람이 만들고, 계산만 앱이 합니다.** 장면의 내용, 설정할지 해결할지, 결말이 좋은지 나쁜지,
비틀기에서 무엇을 고를지는 전부 플레이어 몫입니다. 앱은 규칙에서 실수가 잦은 부분만 맡습니다.

- 1막과 2막이 언제 끝나는지 자동으로 감지
- 1막은 받은 주사위를 남에게 넘기도록, 2막은 본인이 갖도록 강제
- 비틀기와 후기의 흑백 합산 및 표 조회
- 준비 단계에서 규칙대로 끝낼 수 없게 되는 수를 미리 차단

채팅과 음성은 만들지 않았습니다. 통화는 디스코드 같은 걸 따로 켜 두고 쓰세요.

## 실행

필요한 것은 **Python 3.10 이상**과 **Node 18 이상**뿐입니다. 나머지는 스크립트가 알아서 설치합니다.

```bash
git clone https://github.com/NANOliberty/fiasco.git
cd fiasco
./run.sh
```

`http://localhost:8000` 이 열립니다. 처음 한 번은 패키지를 받느라 1~2분 걸리고, 그다음부터는 바로 뜹니다.
파이썬 패키지는 `backend/.venv` 안에만 설치하니 시스템 파이썬은 건드리지 않습니다.

친구들과 하려면 그 주소를 밖에서 접근할 수 있게 열어야 합니다. 가장 간단한 방법은 터널입니다.

```bash
ngrok http 8000          # 또는  cloudflared tunnel --url http://localhost:8000
```

받은 주소를 친구들에게 보내고, 방을 만든 뒤 `링크 복사`로 나온 링크를 나눠 주면 됩니다.

포트를 바꾸려면 `PORT=3000 ./run.sh` 처럼 씁니다.

### 그 밖의 명령

```bash
./run.sh dev      # 코드 고치면 바로 반영 — 백엔드 8000, 화면은 http://localhost:5173
./run.sh test     # 파이썬 테스트 + 프론트 타입 검사
./run.sh smoke    # 브라우저 3개로 한 판을 끝까지 자동 진행 (서버가 떠 있어야 함)
```

## 구조

```
backend/
  app/
    game.py       게임 상태 기계 — 준비·장면·비틀기·후기의 모든 규칙
    playsets.py   플레이세트 표 적재와 간편 준비 해석
    tables.py     비틀기 표, 후기 표, 규칙 요약
    rooms.py      방 저장소와 접속 관리 (메모리)
    main.py       FastAPI — REST + WebSocket
    data/playsets.json
  tests/          게임 전체를 프로그램으로 끝까지 돌려 보는 테스트
frontend/
  src/
    lib/          웹소켓 연결, 상태 컨텍스트, REST 클라이언트
    screens/      랜딩 · 로비 · 준비 · 장면 · 비틀기 · 후기
    components/   주사위, 플레이어 카드, 표 뷰어, 로그
  smoke.mjs       브라우저 3개로 한 판을 끝까지 자동 진행하는 스모크 테스트
```

계정도 DB도 없습니다. 방은 서버 메모리에 있다가 아무도 없는 채로 12시간이 지나면 사라집니다.
상태가 작아서(플레이어 5명 × 주사위 20개 남짓) 변경이 있을 때마다 전체 상태를 브로드캐스트합니다.

## 규칙을 어떻게 옮겼는가

### 준비

주사위 눈이 곧 분류 번호이자 요소 번호입니다. 그래서 요소 하나를 완성하려면 주사위 2개가 듭니다
(분류에 1개, 요소에 1개). 인원 × 4개의 주사위는 **관계 N개 + 세부사항 N개**에 정확히 맞아떨어집니다.

이 때문에 준비 단계에서는 사실상 낭비할 수 있는 주사위가 없습니다. 앱은 매 수마다 "앞으로 규칙대로
끝낼 수 있는가"를 계산해서, 끝낼 수 없게 만드는 행동은 아예 막습니다. 예를 들어 관계를 하나도 만들지
않은 채 세부사항만 쌓으려 하면 거절합니다. 실수했다면 방장이 되돌릴 수 있습니다.

`간편 준비`는 인원수별로 미리 정해진 세트를 표 번호로 되돌려 그대로 깔아 줍니다. 원본 데이터의 표기가
본문과 미묘하게 다른 경우(`맥타운 외곽` ↔ `맥타운: 외곽`, `수퍼마켓` ↔ `슈퍼마켓`)가 있어 정확 일치
대신 유사도로 맞춥니다. 어긋나는 항목들은 테스트에 번호를 못 박아 두었습니다.

### 장면

한 사람이 조명을 받아 `설정`과 `해결` 중 하나만 고릅니다.

| | 장면을 여는 사람 | 결말의 색을 정하는 사람 |
|---|---|---|
| 설정 | 조명 받은 사람 | 다른 사람들 |
| 해결 | 다른 사람들 | 조명 받은 사람 |

1막에서는 받은 주사위를 **반드시 다른 사람에게** 넘겨야 하고, 2막에서는 본인이 갖습니다. 앱이 강제합니다.

막의 끝은 주사위 수로 감지합니다. 중앙 풀이 처음의 정확히 절반이 되면 1막이 끝나고, 다 떨어지면
2막이 끝납니다. 인원 × 4개의 주사위는 막마다 인원 × 2개의 장면이 나오게 되어 있습니다.

### 비틀기

각자 자기 앞 주사위를 굴려 `|흑합 − 백합|`을 냅니다. 검은색 최고점자와 흰색 최고점자가 비틀기 표에서
하나씩 고릅니다.

- 동점이면 동점자끼리 다시 굴려 가립니다. 이 재굴림은 판정에만 쓰고 화면에 표시된 합계는 건드리지
  않습니다 — 숫자가 바뀌면 보는 사람이 헷갈립니다.
- 한 색만 나온 경우에는 그 색의 최고점자와 최저점자가 하나씩 고릅니다.
- 아무도 색이 없으면 차례 순서로 두 사람이 고릅니다.

표를 고를 때 굴리는 주사위는 참고용 난수일 뿐이고, 최종 선택은 자유입니다.

### 후기

2막이 끝나면 각자 가진 주사위를 전부 굴려 흑백의 차이로 후기 표를 봅니다. 값이 0이거나 주사위가
없으면 최악의 결과입니다.

**2막의 마지막 주사위**는 색과 상관없이 가져가는 사람이 결과를 좋은 쪽/나쁜 쪽으로 정할 수 있습니다.
다만 이 지정은 **그 장면의 결말에만** 적용되고, 후기 계산에는 주사위의 실제 색이 그대로 들어갑니다.
규칙에서 가장 헷갈리는 예외라 테스트로 못 박아 두었습니다.

후기 표의 문구는 원서를 그대로 옮기지 않고 각 구간의 의미를 우리말로 새로 썼습니다
(`backend/app/tables.py`).

### 선택 규칙

로비에서 켜고 끕니다.

| 옵션 | 내용 |
|---|---|
| 주사위 개수 조절 | 인당 2/4/6/8개. 늘리면 장면이 늘어 길게 놉니다 |
| 흑백 불균형 | 검은 주사위 비율을 20~80%로. 높일수록 험한 이야기가 됩니다 |
| 마지막 주사위 자유화 | 준비의 마지막 주사위 눈을 원하는 값으로 정합니다 |
| 액셀 밟기 | 방장이 2막을 일찍 끝내고 남은 주사위를 후기용으로 나눕니다 |
| 좋은 주사위/나쁜 주사위 | 몽타주에서 흰색은 긍정, 검은색은 부정으로 선언합니다 |

## 커스텀 플레이세트

로비의 `직접 만들기`에서 표를 채우거나 JSON을 올릴 수 있습니다. 목록 4개(관계/욕망/물건/장소)마다
분류 6개, 분류마다 요소 6개가 필요합니다.

```json
{
  "name": "우리 동네",
  "relationships": { "가족": ["형제자매", "…", "…", "…", "…", "…"], "…": [] },
  "desires":       { "…": [] },
  "objects":       { "…": [] },
  "places":        { "…": [] }
}
```

올린 플레이세트는 서버 메모리에만 있습니다. 서버를 다시 띄우면 사라집니다.

## 테스트

```bash
./run.sh test
```

`backend/tests` 는 게임을 프로그램으로 끝까지 여러 번 돌려 봅니다. 무작위 순서로 진행해도 항상 끝나는지,
막의 경계가 정확한지, 규칙 위반이 거절되는지를 확인합니다.

브라우저 3개를 띄워 실제로 한 판을 끝까지 진행하는 스모크 테스트도 있습니다. 서버를 띄워 둔 채로
다른 터미널에서 돌리세요. 화면 캡처가 `frontend/smoke-shots/` 에 남습니다.

```bash
./run.sh smoke
```

이미 크로미움이 깔린 환경이라 내려받기를 건너뛰고 싶으면 `CHROME_PATH=/경로/chrome ./run.sh smoke`.

## API

| | |
|---|---|
| `POST /api/rooms` | 방 만들기 → 6자리 코드 |
| `GET /api/rooms/{code}` | 방 상태 요약 |
| `POST /api/rooms/{code}/join` | 참가 → `playerId` 와 `token` |
| `GET /api/playsets`, `GET /api/playsets/{id}` | 플레이세트 목록과 표 |
| `POST /api/playsets` | 커스텀 플레이세트 등록 |
| `GET /api/reference` | 비틀기 표와 규칙 요약 |
| `WS /ws/{code}?playerId=&token=` | 상태 동기화 |

웹소켓으로는 `{"type":"action","action":"…","payload":{…}}` 를 보내고, 서버는 변경이 있을 때마다
`{"type":"state","you":"…","state":{…}}` 를 전원에게 보냅니다. 규칙에 어긋나면 보낸 사람에게만
`{"type":"error","message":"…"}` 가 갑니다.

피아스코에는 숨은 정보가 없어서 모두가 같은 상태를 받습니다. 참가 토큰만 빼고 전부 공개입니다.
